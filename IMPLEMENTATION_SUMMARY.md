# Invenza Fine-tuning Implementation - Quick Start

## What We've Built

A complete fine-tuning pipeline for patent-based business idea generation with:

✅ **Data Extraction** — Extract 87K patents from PGVector  
✅ **Embedding Fine-tuning** — Domain pre-training on patent text  
✅ **LLM Fine-tuning** — QLoRA adaptation of qwen2.5-3b  
✅ **Model Router** — Intelligent routing (simple → qwen3:4b, complex → llama3.2)

## Quick Execution Order

### Prerequisites
```bash
# 1. Install Python dependencies
cd Backend
pip install -r requirements.txt

# 2. Ensure Ollama is running
ollama pull llama3.2

# 3. Ensure PostgreSQL with pgvector is running
```

**Phase 2: Embedding Fine-tuning (2-4 hours, GPU)**

```bash
  -d '{"topic": "agriculture"}'
```

**After:** Intelligently routes based on query complexity

```bash
# Returns: {"model_used": "llama3.2", "inference_time_ms": 1250.34}
```

## Key Features

### 1. Query Routing (Token-length based)
- **Simple** (<50 tokens): Routes to qwen3:4b (fast, cost-efficient)
- **Complex** (>50 tokens): Routes to llama3.2 (better quality)
- **Fallback**: If qwen fails, automatically tries llama3.2

### 2. QLoRA Fine-tuning
- LoRA Rank: 8, Alpha: 16 (memory-efficient)
- Only fine-tunes 0.15% of model weights
- Requires just 4-6GB VRAM (vs 12GB for full tuning)
- Saves ~1-2GB disk space (adapter only)

### 3. Model Performance Tracking
- `model_used`: Which model generated the response
- `inference_time_ms`: Latency of LLM inference
- `total_latency_ms`: End-to-end latency (retrieval + inference + scoring)

### 4. Backward Compatible
- Existing API remains unchanged
- New fields are optional (have defaults)
- Router is transparent to users

## Performance Expectations

### Embedding Fine-tuning
- Training time: 2-4 hours (GPU)
- Improves patent similarity matching by ~5-15%
- Re-embedding DB: ~10-20 minutes for 87K patents

### QLoRA Fine-tuning
- Training time: 6-12 hours (GPU, A100 fastest)
- 3 epochs over ~87K patent texts
- Final model size: ~1-2GB (adapter only)
- Per-sample training time: ~3-5 seconds (with batch size 8)

### Inference (after fine-tuning)
- qwen3:4b: 100-300ms (simple queries)
- llama3.2: 500-1500ms (complex queries)
- Token efficiency: 40-60% cost reduction on simple queries

## Troubleshooting

### "CUDA out of memory"
→ Reduce batch size or use CPU for fine-tuning
```bash
python scripts/finetune_embeddings.py --batch-size 4
```

### "Connection refused" (Ollama)
→ Start Ollama: `ollama serve`

### "PostgreSQL connection failed"
→ Check DATABASE_URL in .env

### "Model not found"
→ Ensure fine-tuning completed and model directory exists
```bash
ls -la models/qwen_patent_qlora/
```

## Architecture Diagram

```
User Query (topic)
       ↓
  Model Router (classify complexity)
  ├─ Simple (<50 tokens) → qwen3:4b (fine-tuned + LoRA)
  └─ Complex (>50 tokens) → llama3.2 (Ollama)
       ↓
   Retrieve Patents (PGVector + fine-tuned embeddings)
       ↓
    Build Prompt (patent evidence)
       ↓
  Generate Idea (selected model, ~25-100 tokens)
       ↓
  Score Grounding (hybrid scorer)
       ↓
  Return Response (with model_used & latency tracking)
```
